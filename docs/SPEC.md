## 1. 개요

- **한 줄 정의**: 블록 조각을 8x8 보드에 놓아서 가로·세로 줄을 채워 지우는 **블록 퍼즐** 게임
- **벤치마크**: 블록 블라스트 (Block Blast) 방식
- **목적**: v0.1에서는 장르의 기본 게임 메커니즘을 구현해 플레이 경험과 재미를 검증한다. 드래그 앤 드롭, 그리드 스냅, 조각 생성 알고리즘, ddooby-pang 인프라(인증, 랭킹) 재활용을 학습한다
- **1차 사용자**: 조카 (ddooby-pang과 같은 테스터)
- **이후 계획**: 피드백 반영 → 버전업 → 출시 검토
- **제품 방향**: 캐주얼 플레이를 중심으로 하되, 몇 수 앞을 생각하는 전략적 재미를 더한다. v0.1은 기본 게임 완성에 집중하고 독자적인 특수 규칙·차별화 기능은 후속 버전에서 검토한다
- **원칙**: Block Blast 등 기존 게임의 장르 공통 메커니즘은 참고하되, **그래픽, 이름, UI, 사운드, 브랜드는 복제하지 않고 독자적으로 제작한다**

### 1.1 ddooby-pang과의 관계

| 항목 | ddooby-pang | ddooby-block |
|---|---|---|
| 장르 | 매치-3 | 블록 퍼즐 (줄 채우기) |
| 조작 | 스왑 | **드래그 앤 드롭** |
| 중력 | 있음 (낙하, 연쇄) | **없음** (놓은 자리에 고정) |
| 긴장감 | 이동 수 / 시간 | **공간 관리** |
| 진행 | 스테이지 + 타임어택 | **무한 점수** (게임 오버까지) |
| 데이터 | ddooby-pang 전용 Supabase | **ddooby-block 전용 Supabase** |
| 재활용 | — | **코드와 설계 패턴만**: 스택 세팅, seeded RNG, 로컬 저장, 익명 로그인 흐름, 닉네임, 주간 랭킹, 리플레이 검증 |

- **독립된 게임이다.** 레포, Supabase 프로젝트, 계정, 데이터 모두 따로 둔다 (**1게임 1DB 원칙**)
- **착수 시점**: ddooby-pang v0.2 **3주차(Supabase + 랭킹) 완료 후**. 검증된 인증·랭킹 코드를 복사해 오기 위해서다. 그 전에는 기획과 설계만 진행한다
- 공통 코드는 **복사**한다. 공통 패키지로 묶지 않는다 (두 게임의 독립성 유지)

## 2. 목표 / 비목표

### 목표 (v0.1)
- 8x8 보드에 조각 3개를 드래그해서 놓을 수 있다
- 가로·세로 줄이 꽉 차면 제거되고, **동시 다줄 클리어**와 **연속 콤보**에 보너스가 붙는다
- 남은 조각을 하나도 놓을 수 없으면 게임 오버
- **클래식 모드** (무한 점수) 하나
- 로컬 최고 점수 + **주간 랭킹** (ddooby-pang 인프라 재활용)
- 게임 중 앱을 꺼도 **이어하기** 가능
- Android APK + 웹(GitHub Pages)

### 비목표 (v0.1에서 안 함)
- 조각 회전
- 어드벤처(스테이지) 모드
- 아이템 / 되돌리기 / 부활
- SNS 로그인 (ddooby-pang v0.3과 같이 진행)
- 광고, 과금
- iOS 네이티브 빌드

## 3. 코어 규칙

### 3.1 보드
- 8x8 빈 보드로 시작한다
- 칸 상태: 빈 칸 / 채워진 칸 (+ 표시용 색상)
- 색상은 **조각 종류별 고정 색**이다. 게임 규칙에는 영향을 주지 않는다

### 3.2 조각 (Piece)
- 하단 트레이에 **조각 3개**를 제시한다
- 3개를 **모두 놓으면** 새 조각 3개를 제시한다
- **회전 불가.** 제시된 모양 그대로 놓는다
- 조각 세트 (v0.1, 회전 불가라 방향별로 별도 조각):

| 그룹 | 조각 | 칸 수 |
|---|---|---|
| 점 | 1x1 | 1 |
| 직선 | 1x2, 1x3, 1x4, 1x5 (가로 / 세로 각각) | 2~5 |
| 사각형 | 2x2, 3x3, 2x3, 3x2 | 4~9 |
| L 소형 | 3칸 L (4방향) | 3 |
| L 대형 | 5칸 L (3x3 모서리형, 4방향) | 5 |
| T | 4칸 T (4방향) | 4 |
| S / Z | 4칸 (가로 / 세로) | 4 |

- 조각별 **가중치**를 `config`로 관리한다 (3x3처럼 큰 조각은 낮게)

### 3.3 조각 생성 규칙 (공정성 보정)
- 기본은 **seed 기반 가중치 랜덤**이다
- 3개를 생성할 때 **현재 보드에 최소 1개는 놓을 수 있도록** 보정한다
  - 생성한 3개가 모두 놓을 수 없으면 재추첨 (최대 N회, 이후 놓을 수 있는 조각 중에서 선택)
- 3개 **전부**가 놓을 수 있다는 보장은 하지 않는다 (긴장감 유지)
- 보정 로직도 seed로 **완전히 재현 가능**해야 한다 (리플레이 검증 전제)
- v0.1의 보정은 **세 조각을 모두 배치할 수 있는 경로를 보장하지 않는다**. 최소 1개 배치 가능 조건만 보장한다

#### 3.3.1 후속 버전 후보 — 전략형 보정 (v0.1 미포함)

- 현재 보드를 기준으로 Seed 기반 후보 트레이를 여러 개 생성하고 최대 3수의 배치 경로를 평가한다.
- 세 조각을 모두 놓을 수 있는 후보를 **우선 고려**하되, 모든 트레이의 완주 가능성을 **보장하지 않으며** 완주 경로가 없는 트레이도 일부 허용한다.
- 배치 가능한 첫 수, 배치 순서 의존성, 조각 배치 후 공간 활용도 등을 난이도 판단의 후보 지표로 삼는다.
- 후보 수·탐색 한도·허용 비율·적용 버전은 시뮬레이션과 사용자 플레이 테스트 후 결정한다. 현재 v0.1의 규칙이나 수용 기준을 변경하지 않는다.

### 3.4 배치
```
조각 드래그 → 보드 위에서 그리드 스냅 → 고스트 미리보기
   ├─ 놓을 수 있음 → 손 떼면 배치 → 줄 판정 → 제거 → 점수
   └─ 놓을 수 없음 → 손 떼면 트레이로 복귀 (페널티 없음)
```
- 드래그 중인 조각은 손가락보다 **약 1.5칸 위**에 띄워서 표시한다 (손가락에 가려지지 않게)
- 고스트 미리보기 중 **채워질 줄을 하이라이트**한다
- 겹치거나 보드 밖으로 나가면 놓을 수 없다

### 3.5 줄 제거
- 배치 후 **가로 줄과 세로 줄을 동시에** 검사한다
- 꽉 찬 줄은 전부 **한 번에** 제거한다 (가로와 세로가 교차하는 칸도 한 번만 제거)
- 중력 없음. 제거된 칸은 빈 칸으로 남는다

### 3.6 게임 오버
- 트레이에 남은 조각 중 **어떤 것도** 보드 어디에도 놓을 수 없으면 게임 오버
- 배치할 때마다 검사한다

## 4. 점수

| 항목 | 점수 |
|---|---|
| 조각 배치 | 칸 수 × 1 |
| 1줄 제거 | 100 |
| 2줄 동시 | 300 |
| 3줄 동시 | 600 |
| 4줄 이상 동시 | 1000 + 추가 줄당 500 |
| **보드 전체 비우기** | +3000 |

### 4.1 콤보
- 줄을 제거한 배치가 이어지면 콤보 카운트가 올라간다
- 줄을 못 지운 배치가 **3번 연속**이면 콤보가 끊긴다 (유예 2회)
- 줄 제거 점수에 콤보 배율: `1 + 0.5 × (combo - 1)`

> 수치는 플레이 테스트 후 조정한다. 하드코딩하지 말고 `config`로 분리한다.

## 5. 연출 (Juice)

ddooby-pang 조합 연출과 같은 원칙이다. **보는 맛이 핵심**이다.
- 줄 제거: 줄을 따라 순차 파티클 + 효과음
- 다줄 동시 / 콤보: 텍스트 팝업 ("더블!", "트리플!", "콤보 x3!") + 화면 흔들림 (단계에 비례)
- 보드 전체 비우기: 전용 연출
- 게임 오버 직전: 놓을 수 없는 조각을 흐리게 처리
- 연출(view)과 결과(core)는 분리한다

## 6. 화면 구성

```
[타이틀] → [메인] ─┬─ [게임] → [게임 오버: 점수, 최고 점수, 랭킹 순위]
                    ├─ [주간 랭킹]
                    └─ [이어하기] (진행 중인 판이 있을 때만)
```
- 게임 HUD: 현재 점수 / 최고 점수 / 콤보 표시 / 일시정지
- 세로 화면 고정, 한 손 조작 기준
- 하단 트레이는 엄지가 닿는 위치

## 7. 저장

| 데이터 | 위치 |
|---|---|
| 최고 점수 | 로컬 |
| **진행 중인 판** (보드, 트레이, 점수, 콤보, RNG 상태, 배치 로그) | 로컬, **배치할 때마다 저장** |
| 주간 기록 | ddooby-block 전용 Supabase |

- 무한 게임이라 한 판이 길다. 앱이 꺼져도 **이어하기**가 돼야 한다
- RNG 상태와 배치 로그를 같이 저장해야 이어한 판도 리플레이 검증이 된다

## 8. 주간 랭킹 (ddooby-pang 설계 패턴 재활용)

- **ddooby-block 전용 Supabase 프로젝트**를 새로 만든다. ddooby-pang과 계정·닉네임·데이터를 공유하지 않는다
- 테이블 구조는 ddooby-pang의 `supabase/migrations/`를 **복사해서** 시작하고, block에 맞게 고친다

```sql
profiles       (id uuid PK -> auth.users, nickname text, tag int, created_at)
runs           (id uuid PK, user_id, seed int, created_at, submitted bool)
weekly_scores  (user_id, week_key text, best_score int, run_id, updated_at,
                PRIMARY KEY (user_id, week_key))
```
- 이어하기 데이터는 서버에 두지 않고 로컬에만 저장한다 (7장)
- 인증: Supabase **익명 로그인** + 닉네임 (SNS 로그인은 이후 버전)
- RLS: `weekly_scores`는 전체 읽기, 클라이언트 쓰기 금지 (Edge Function만 쓰기)
- 주 단위: 매주 월요일 00:00 KST 초기화, 1인 1기록 (최고 점수만)

### 8.1 점수 검증

```
게임 시작 → start-run → run_id + seed 발급
게임 오버 → submit-score
   { run_id, seed, placements: [{ trayIndex, row, col, t }], clientScore, version }
      ├─ core로 리플레이 → 점수 재계산, 불일치 시 거부
      ├─ 재사용된 run_id 거부
      ├─ 배치 간격이 사람 한계 미만이면 거부
      └─ 통과 → weekly_scores upsert
```
- 시간 제한이 없는 게임이라 시간 검증은 **최소 간격**만 본다
- 이어하기로 며칠에 걸친 판은 **시작한 주** 기준으로 등록한다

## 9. 기술 스택

| 영역 | 선택 |
|---|---|
| 게임 엔진 | Phaser 3 |
| 언어 | TypeScript (strict) |
| 빌드 | Vite |
| 모바일 패키징 | Capacitor (Android 우선) |
| 백엔드 | Supabase (**ddooby-block 전용 프로젝트**) |
| 로컬 저장 | Capacitor Preferences / localStorage + `navigator.storage.persist()` |
| 테스트 | Vitest |
| 배포 | GitHub Pages + APK |

### 9.1 아키텍처 원칙
- **게임 로직은 Phaser를 import하지 않는 순수 TS** (`src/core/`)
  - 보드, 조각 정의, 배치 가능 판정, 줄 제거, 조각 생성(보정 포함), 점수, 콤보, 게임 오버
  - 입력: 상태 + 액션(배치) → 출력: 새 상태 + 이벤트 목록
- Phaser는 이벤트를 받아 **애니메이션과 입력만** 담당한다
- 8x8 보드라 `canPlace` 전수 검사(조각 3개 × 64칸)는 충분히 빠르다. 최적화(비트마스크)는 필요할 때만

```
src/
├── core/        # Board, Pieces, Generator, Rules, Scoring
├── scenes/      # Boot, Menu, Game, GameOver, Ranking
├── view/        # 보드, 조각, 드래그, 고스트, 이펙트
├── data/        # 조각 세트, config
├── storage/     # 최고 점수, 이어하기
└── online/      # Supabase 클라이언트, 랭킹 (ddooby-pang에서 복사)
```

## 11. 수용 기준

- [ ] 조각을 보드 밖이나 채워진 칸에 놓으면 트레이로 돌아간다
- [ ] 가로와 세로가 동시에 차면 한 번에 제거되고, 교차 칸은 중복 계산되지 않는다
- [ ] 생성된 조각 3개 중 최소 1개는 현재 보드에 놓을 수 있다 (seed 1~1000 테스트)
- [ ] 남은 조각을 하나도 놓을 수 없으면 즉시 게임 오버가 된다
- [ ] 콤보가 줄을 못 지운 배치 3회 연속에서 끊긴다
- [ ] 같은 seed와 배치 로그를 넣으면 클라이언트와 서버 점수가 **항상 같다**
- [ ] 앱을 강제 종료하고 다시 열면 같은 보드, 트레이, 점수로 이어진다
- [ ] 이어한 판도 리플레이 검증을 통과한다
- [ ] ddooby-block 전용 Supabase에만 기록되고, ddooby-pang 데이터와 섞이지 않는다
- [ ] 드래그 중 조각이 손가락에 가려지지 않는다

3. **콤보 유예 횟수**: 2회(기본값) vs 0회(바로 끊김)
4. **회전**: 불가(기본값). 허용하면 난이도가 크게 내려간다
5. **조각 세트**: 3.2 표의 조각 구성과 가중치 → 플레이 테스트 후 조정
6. **그래픽**: 단색 블록 + 하이라이트(기본값) vs 무료 에셋
